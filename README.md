# KsaDevPanel

KsaDevPanel is a private developer workbench for Kitten Space Agency. Open it with **F12**, the default configurable shortcut. The Runtime Console shows the run ID and recent lifecycle diagnostics and can copy a bounded report. The **Lifecycle** tab reports the observed scene, flight-world readiness, active vessel availability, and age of the last successful vessel snapshot. The Vessel Inspector shows a read-only snapshot of the active craft: altitude, surface and orbital speed, ECL speed, acceleration, total and propellant mass, manual throttle, vessel identity, and parts. The current prerelease is `0.2.0-alpha.1`.

This prerelease targets Windows x64 KSA `2026.11.25.5949`, StarMap loader and API `0.5.4`, and loader-provided Harmony `2.4.3`. Build with the Windows x64 .NET SDK `10.0.100`. See [Compatibility](docs/Compatibility.md) for exact inputs and [Verification](docs/Verification.md) for what has been exercised. Use the shared workspace development copy and profile described in [Development](docs/Development.md) for all mods.

The Performance tab reports the CPU model and OS-reported average current frequency, KSA process and system CPU/memory, and per-process GPU engine and video-memory data once per second. Select a metric to graph up to five minutes of rolling history. GPU identity and memory are shown only when the running process's GPU Engine LUID can be matched to one DXGI adapter; GPU clock speed is omitted. The Process CPU graph has been observed in the isolated `.5949` instance; hardware readings still need comparison with Windows Task Manager.

The isolated workbench and live telemetry were observed in one .5949 freefall test world. Altitude is reported in km by the pinned API. Other speed, acceleration and mass scales, throttle range, powered/coasting response, vessel switching, scene transitions, shortcut conflicts and restart persistence still need verification. The Lifecycle tab reports only the scenes observable through the current StarMap callback and KSA readiness flags; transitions, editor and menu behavior still need runtime verification. See the acceptance scenarios in [Testing](docs/Testing.md) and current outcomes in [Verification](docs/Verification.md).

Use [Development and deployment](docs/Development.md) to compile, stage, and install into a disposable game copy and isolated profile. If the workbench does not open, check the startup marker, effective profile, manifest enablement, and the local shortcut settings. See [Testing](docs/Testing.md) for the corresponding checks.

The **Set Orbit** tab selects a destination body from the loaded system and configures circular altitude or periapsis and apoapsis, inclination, node, argument of periapsis, and placement angle (true anomaly). Review the preview and select **Apply orbit and teleport now** at 1× with auto warp off. The stock input queue moves the active vessel on processing. Altitudes are relative to the body's reference radius.

While the game is running, the **Settings & Refresh** tab watches the isolated `KsaDevPanel.settings.json` file and applies valid shortcut and window layout edits on the UI thread. It also has a **Reload settings now** button. On first launch, the mod creates that file under `.development/profile/`. Edit its `Hotkey`, `Visible`, `X`, `Y`, `Width`, or `Height` values; malformed JSON leaves the last working settings active. This refreshes panel settings only. Changes to C# code still require rebuilding, closing the game, deploying, and launching again.

Source and the loader manifest are in `src/KsaDevPanel/`. Deployment tools are in `tools/`, portable checks in `tests/`, and technical notes in `docs/`. See [Architecture](docs/Architecture.md), [Changelog](CHANGELOG.md), and [Roadmap](docs/Roadmap.md). Universe Inspector and the remaining workbench tools are planned.
